# イベントと呼び出し経路

## 呼び出し経路

reconciler を起動する経路は 3 つである。それぞれのトリガ方式とペイロードを、以下に示す。

| 種別 | トリガ方式 | ペイロード |
|---|---|---|
| 定期実行 | EventBridge Scheduler `rate(5 minutes)` | `{}` |
| RDS 自動起動 | EventBridge ルール (`aws.rds` イベント) を起点とした Lambda の実行 | EventBridge イベント |
| 手動 | `aws lambda invoke` 等 | `{}` |

## 多重実行の排除

reconciler は DynamoDB の `LOCK` / `RECONCILE` にグローバルリースを取得し、各呼び出し経路をまたぐ多重実行を防ぐ。リースを取得できない呼び出しは、設定や AWS リソースを読み書きせず成功として終了する。

Lambda の reserved concurrency も 1 を推奨する。排他性はリースが担保するが、予約同時実行数によってリース取得前後の不要な呼び出しと課金を抑えられる。

## RDS 自動起動イベント

RDS インスタンス・Aurora クラスターの最長停止期間は 7 日間であり、当該期間経過後に自動で起動される。自動で起動したインスタンス・クラスターをスケジュールに準拠した状態にするため、起動時に発行される EventBridge イベントを起点として、reconciler を実行する。

> [!NOTE]
> このイベントは、意図的にリソースを起動した場合にも発行される。したがって、全てのイベントでリソース操作が必要になるとは限らない。

### 処理するイベント

購読する EventID を、以下に示す。

| EventID | 意味 |
|---|---|
| `RDS-EVENT-0088` | インスタンス起動完了 |
| `RDS-EVENT-0151` | クラスター起動完了 |

## SNS 通知

環境変数 `NOTIFICATION_TOPIC_ARN` 設定時のみ実行される。

### 通知の種別

件名は `[cheapskate] <種別>: <グループ名>/<リソース ID>`、本文は JSON オブジェクト 1 つである。

通知の種別と、その本文および発行の契機を、以下にまとめる。

| 種別 | 件名の種別部分 | 本文の属性 | 発行の契機 |
|---|---|---|---|
| アクション | `start`, `stop` | `group`, `resource_id`, `operation_id`, `action`, `desired`, `at` | リソースの start/stop を実行したとき |
| 失敗 | `error` | `group`, `resource_id`, `error`, `at` | リソース単位・グループ単位の失敗を記録したとき |
| 復旧 | `recovered` | `group`, `resource_id`, `at` | 記録済みの `last_error` が解消したとき |

グループ単位の失敗・復旧では、`resource_id` が `group#<グループ名>` になる。

### 重複排除

失敗通知は、初回とエラー内容の変化時のみ発行する。同一エラーの継続中は `status#` への記録のみ行う。

復旧時は `recovered` を 1 回通知し、`last_error` をクリアする。アクションの成功に伴う復旧は、アクション通知が兼ねるため別途の復旧通知を行わない。

グループ単位のエラーのクリアは、そのグループの処理をすべて終えたあとに 1 回だけ行う。探索直後にクリアしてからリソースのループでまたグループ単位のエラーを記録すると、毎サイクル「クリアして通知 → 記録して通知」を繰り返す通知フラップになる。

### 件名の制約

SNS の Subject 制約(ASCII、100 文字)に合わせ、件名の非 ASCII 文字は `?` に置換して切り詰める。完全なリソース ID は本文に含まれる。

### 通知の失敗

アクション成功後の Publish 失敗はアクションをエラー扱いにしない。同じ処理内で同じ `operation_id` により 1 回だけ再送し、2 回とも失敗した場合は送信を打ち切る。Status に通知待ちは残さず、次の AWS 操作を停止しない。通知本文の `at` はアクションの時刻を保持するため、受信順にかかわらず操作の前後関係を判定できる。
